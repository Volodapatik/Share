# QR-Bridge

Експериментальна **клієнтська** (без бекенду) платформа для передачі файлів між
двома смартфонами через оптичний канал — потік QR-кодів, що швидко змінюються
на екрані одного пристрою й зчитуються камерою іншого.

Використовує спрощений **систематичний fountain-код** (у дусі Luby Transform /
подібно до проєктів на кшталт `txqr`), тому втрачені або задубльовані кадри
не зупиняють передачу — приймач просто чекає, доки не набереться достатньо
"корисних" кадрів, щоб відновити файл повністю.

**Жива версія:** https://volodapatik.github.io/Share/

## Як це працює коротко

1. **Відправник** ділить файл на `K` блоків фіксованого розміру.
2. Перші `K` кадрів — це самі блоки без змін (систематична частина).
3. Далі йдуть нескінченні "repair"-кадри: XOR кількох випадково (але
   детерміновано, за seed = sessionId+esi) обраних блоків.
4. Кожен кадр кодується у QR у byte-mode (сирі байти, без base64), з
   компактним заголовком (сесія, номер кадру, кількість блоків, розмір блоку).
5. **Приймач** сканує камерою, парсить заголовок, XOR-ить символ із уже
   відомими блоками (peeling-декодер) — і поступово "розплутує" всі `K`
   блоків, навіть якщо частина кадрів не була зчитана.
6. Окремі "meta"-кадри (кожен 8-й) несуть ім'я файлу, MIME-тип, точний
   розмір і CRC32 для перевірки цілісності.
7. Коли всі блоки відновлені й контрольна сума збігається — файл автоматично
   зберігається (download) на приймачі.

## Структура проєкту

```
Share/
├── index.html   — розмітка, перемикач Sender/Receiver, панелі статистики
├── style.css    — мобільний темний інтерфейс
├── app.js       — вся логіка: кодек кадрів, fountain-код, генерація QR, сканування
└── README.md
```

Зовнішні залежності підключаються з CDN прямо в `index.html`:
- [`qrcode`](https://github.com/soldair/node-qrcode) — генерація QR (byte-mode, canvas)
- [`jsQR`](https://github.com/cozmo/jsQR) — сканування/декодування QR з камери

## Використання (важливо!)

1. На одному телефоні → вкладка **«Відправник»** → оберіть **невеликий файл** (краще ≤ 100–200 КБ) → «Почати трансляцію».
2. На другому → вкладка **«Отримувач»** → «Увімкнути камеру» → наведіть на екран першого так, щоб QR повністю був у кадрі.
3. Стежте за бейджем:
   - **НЕМАЄ СИГНАЛУ** — QR не видно / не розпізнається
   - **QR ВИДНО** (жовтий) — камера бачить QR, але кадр ще не наш
   - **СИНХРОНІЗОВАНО** (зелений) — йде прийом даних
4. Коли прогрес досягне 100% і CRC збіжиться — файл автоматично завантажиться.

### Поради для стабільного зчитування
- Тримайте телефони **паралельно**, відстань 15–40 см.
- Мінімізуйте відблиски (не під прямим світлом / сонцем).
- Якщо погано ловить — зменшіть **розмір блоку** до 60–80 B і FPS до 8–12.
- Великі файли (десятки МБ) **непрактичні** — оптичний канал дає ~0.5–2 КБ/с.

## Параметри

- **Розмір блоку** — більший = менше кадрів, але щільніший QR (гірше сканується з екрана).
- **FPS** — 8–15 зазвичай найстабільніше. Вище 20 часто дає рвані кадри через rolling shutter камери.

## Відомі обмеження (прототип)

- Швидкість обмежена рендером QR + декодуванням jsQR з екрана (не мережею).
- Fountain-код спрощений (не повний Robust Soliton).
- Немає адаптивного підбору параметрів під якість каналу.
- Найкраще працює з файлами до ~200–300 КБ.
